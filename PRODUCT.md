# Product

## Register

product

## Users

A reviewer or mentor evaluating a portfolio demo. They open the app expecting competent code — they should instead find intentional design decisions that signal craft. The secondary user is the intern/student who built it, demonstrating they can think about UX and visual quality, not just functionality.

## Product Purpose

A store inventory management SPA — products and categories, with CRUD operations and category filtering. The product exists as a learning project and portfolio artifact. Success means a reviewer pauses on the UI and thinks "this person thought about design", not "this is a CRA starter."

## Brand Personality

Calm, efficient, modern. Soft without being weak. The interface should feel like it was considered, not assembled. Pastel color use as structure and hierarchy — not decoration.

## Anti-references

- Generic purple-gradient SaaS ("AI slop" aesthetic — gradient buttons, glowing cards, purple-on-dark patterns)
- Bootstrap-default weight and density
- Dark-mode-as-default because "tools look cool dark"
- Emoji, decorative icons, or visual noise
- Extra dependencies beyond React and TypeScript — design craft through plain CSS and component structure only

## Design Principles

1. **Deliberate over default.** Every spacing value, color choice, and layout decision should look like someone made it on purpose. Nothing should look like it came from a template.
2. **Calm efficiency.** The UI gets out of the way of the content. No competing for attention. Pages feel open, not packed.
3. **Color as structure.** Pastels carry hierarchy and differentiation — not used decoratively, but to help the eye navigate.
4. **Craft within constraints.** No extra libraries. All visual quality comes from typography, spacing, and color — the fundamentals.
5. **Portfolio legibility.** Every screen should be screenshot-ready. A reviewer skimming fast should see intentional decisions within two seconds.

## Accessibility & Inclusion

WCAG AA. System font stack acceptable. No reduced-motion considerations required for now, but avoid layout-animating properties if motion is added later.
